# PWP — карта проекта для агентов

PWP — тактический шутер «Squad в Minecraft» (Forge 1.20.1, Java 17), мультимодульный Gradle-проект (`com.pigeostudios.pwp`). Игра про командную тактику, а не киллы: тикеты, точки захвата, отряды, фобы/ралики, медицина, техника 4 фракций, прогрессия (Coins/XP/20 рангов/престижи/скины/боевой пропуск). Режимы: AAS (обе команды захватывают точки по порядку) и Invasion (асимметричный).

Пистолетные патроны: P320 — `.45 ACP`; M2HB — `tacz:50bmg` (не 127x108); MRAD — `ea:416barrett`. Раскладка: слот 0 — мейн ган (СТВОЛ), слот 1 — пистолет (ВТОРИЧКА), слот 2 — гранаты, **слот 3 — СПЕЦ: фирменное оружие роли** (труба у LAT/HAT, M320 у гренадёра, мины у сапёра, клеймор у снайпера, Игла у ПВО) — у этих ролей дым/бинт сдвинуты на слоты 4-5; метки слотов 0-3 захардкожены в коде (PRIMARY/SECONDARY/THROWABLE/SPECIAL), поэтому спец-оружие лежит физически на слоте 3, а не помечается `__ALT__`

## Конвенции кода

- UI только через `GuiGraphics`: `fill()`, `blit()`, `drawString()`, `enableScissor()`, абсолютное позиционирование x/y — никакого HTML/CSS/flexbox
- Все цвета/отступы/типографика из дизайн-системы `PWPTheme.java` (ARGB, `Spacing.*`, `TextStyle.*`) — никаких магических чисел
- Локализация: `assets/<modid>/lang/{en_us,ru_ru,uk_ua}.json` + `Component.translatable("key")`
- Mixins: конфиги в `src/main/resources/<mod>.mixins.json`, код в пакетах `mixin`; клиентский код — `@OnlyIn(Dist.CLIENT)`
- Mixin-модули обязаны подключать плагин `org.spongepowered.mixin` (mixingradle 0.7-SNAPSHOT в buildscript) + `annotationProcessor 'org.spongepowered:mixin:0.8.5:processor'`, объявлять `refmap` в mixins.json и иметь guard на `jar` (сборка падает, если рефмапа нет в jar — см. `pwp-core-client/build.gradle`). Без рефмапа миксины по mojmap-именам не находят таргеты в проде (SRG) — краш клиента (был инцидент 02.08.2026: `LevelTransitionMixin` на `setLevel`)
- Mixin AP ломается на генерик-методах, наследуемых подклассами (`Screen.addRenderableWidget` дублируется в tsrg ForgeGradle): НЕ использовать `@Invoker` для таких методов (ScreenInvoker удалён); доступ к полям цели — через `@Accessor` (рефмап-запись генерируется стабильно, `ConnectScreenAccessor`/`DisconnectedScreenAccessor`), НЕ через `@Shadow` (записей в рефмапе нет). Инжект в унаследованный метод — только с owner-квалификацией (`method = "Lnet/.../Screen;mouseClicked(DDI)Z"`)
- Миксины на ЧУЖИЕ моды (SBW/pointblank): Mixin AP не имеет SRG/MCP-маппингов для их методов и падает с ошибкой «Unable to locate obfuscation mapping» — на `@Inject` обязателен `remap = false`, таргет-класс — прямой `@Mixin(Класс.class)` через `compileOnly files(...)` прод-жарник. ПРЕДПОЧТИТЕЛЬНО вместо миксинов на чужие классы — единая точка входа на vanilla (`ServerLevel.addFreshEntity` + `instanceof`-проверки по интерфейсам чужих модов + серверный тикер) — так покрываются любые будущие аддоны без новых миксинов (пример: `sbwchunkload` v1.1+). Server-only миксины класть в секцию `server` mixins.json
- Комментарии и документация — на русском

## Обфускация pwp-модов (ProGuard)

- Пайплайн: `build-obfuscate.bat` на рабочем столе = копия `build.bat` + шаг `gradlew obfuscatePwpMods` (корневой `build.gradle`, конфиг `proguard.pro`). Обычный `build.bat` НЕ обфусцирует. Результат: `PWP/build/obfuscated/*.jar` + `mapping.txt` (для retrace стектрейсов прода)
- Режим: `-dontshrink -dontoptimize` — только переименование имён; библиотеки: `forge-<ver>-srg.jar` из кэша ForgeGradle + прод-жарники geckolib/curios/voicechat из Pwpfiles (без них ProGuard переименует override-методы vanilla/GeckoLib — игра молча сломается)
- Keep-правила (что нельзя переименовывать): миксин-пакеты целиком (рефмап), `@Mod` классы, рефлексия лобби (`LobbyMod.voteMode`, `VotingManager.vote`, `FactionVotingManager.vote`, `MatchAllocator.joinActiveMatch/joinMatchById`), поля `ServerManager$ServerMatchConfig` (Gson-маппинг match_config.json по именам полей), константы всех enum (`.name()` уходит строками клиенту — `MatchPhase.STARTING/PLAYING/ENDING`), пакет `voicechat` (ASM-скан Forge по `@ForgeVoicechatPlugin`)
- ПРАВИЛО НА БУДУЩЕЕ: добавил `Class.forName`/`getMethod` по имени на наши классы или Gson-маппинг POJO по именам полей — ОБЯЗАН добавить keep-запись в `proguard.pro`, иначе в обфусцированном релизе сломается молча. Новые миксины в существующих пакетах покрываются автоматически; новый модуль — добавить в `MODS_LIST` в build.bat и в `pwpModules` в корневом `build.gradle`

## Античит (архитектура v2, с 04.08.2026)

- **Java-агент НИКОГДА не кикает сам** — только репортит на core-service и кикает по ответу `{action: kick}` (архитектура PJM Launcher). Инцидент 04.08.2026: локальный сканер маркеров убивал игру из-за класса `CalendarAstronomer$Horizon` (ванильная библиотека ICU4J, слово «Horizon» совпало с маркером чит-клиента) — локальных киков больше нет
- Код агента: `PWP-Launcher/anticheat-agent/` (`Agent.java` + `O.java` — XOR-обфускация маркеров, сборка `build.ps1` + ProGuard `agent.pro`, ключ модуля `java.net.http` в libraryjars). Публикация: `Pwpfiles/anticheat/agent.jar` + SHA-256 в `artifacts.json` + подпись `node PWP-Launcher/scripts/sign-file.mjs artifacts.json` (ключ в `%APPDATA%\.pwplauncher\.private\ed25519-private.pem`, тот же, что подписывает manifest.json)
- Агент ходит на сервер напрямую (`-Dac.url`, заголовок `X-Launch-Token`): `GET /api/v1/launcher/anticheat/rules` (правила {pattern,matchType,hash,severity} + version), `POST /detect` и `/files` и `/heartbeat` (отвечают `{action: kick|none}`; heartbeat продлевает сессию на 30 мин и возвращает `blacklistVersion` для ре-фетча). Seed-маркеры (severity 0) — только телеметрия, кикают лишь правила из БД с severity >= banSeverity (конфиг `anticheat.banSeverity`, дефолт 100 = всё report-only)
- Эвристика `illegal-class-name` (нестандартные символы в имени класса) с 04.08.2026 применяется ТОЛЬКО к классам вне доверенных корней: лаунчер передаёт `-Dac.trusted` (файл со списком корней `mods/` + `libraries/`), классы из них и bootstrap/jrt не проверяются. Причина: реворк 04.08.2026 потерял trusted-проверку и агент слал 20 фейковых детектов на каждый запуск игры (Forge/mixin/Nashorn генерируют рантайм-классы с нестандартными именами; во всех jar-ах игры нелегальных имён нет). Сканирование по блэклисту (hash/строки) работает по всем классам без исключения. Пойманные имена агент дополнительно пишет в `ac_illegal_names.log` рядом с kick-флагом (сервер имя класса не хранил — столбец `details` добавлен в `anticheat_detections` с 04.08.2026)
- `anticheat_detections`: столбец `details` (имя класса/детали), дедуп одинаковых `(player_uuid, type, signature)` в окне 10 минут (один буст = одна запись), TG-алерт шлётся только на первую запись буста
- Таблица `anticheat_blacklist`: match_type = substring|exact|word|regex|hash|string-literal, колонки `hash` (SHA-256 байткода) и `updated_at` (версия правил); `anticheat_sessions.revoked` — отзыв сессии. Админка: `/api/v1/admin/anticheat/signatures`
