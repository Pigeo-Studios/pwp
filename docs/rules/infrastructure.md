# Правила: инфраструктура / запуск

Часть правил PWP. Полный индекс — корневой `AGENTS.md`.
**Перед изменением кода этого модуля/домена — прочитай этот файл; после изменений (новый модуль/фича, инцидент, фикс, изменённые правила сборки) — обнови его**: текст на русском, метки дат `(дд.мм.2026)`, удаляй устаревшее, если описание разошлось с кодом, секреты/токены не добавлять.

---

- MySQL (XAMPP), БД `pwp_core`; core-service на :8080; Caddy — HTTPS-прокси `https://pigeo.asuscomm.com` → localhost:8080 (Caddyfile в корне); MC-сервер :25565
- Discord RPC: лаунчер слушает `127.0.0.1:42157` (`POST /status` с `{"state":"lobby|match|playing|idle","nickname":...,"faction":...}`) и ставит статус в Discord. Мод шлёт статус через `LauncherStatusReporter` (pwp-warfare/client): `handleSyncGameData` постит lobby/match (своя фракция против вражеской), отключение от сервера — playing
- Матч-серверы поднимаются пер-матч из `match_template/` (директории `match_*` gitignored)
- **ОПЦИОНАЛЬНЫЕ МОДЫ НИКОГДА не ставить на сервер** (`PWP-Server/mods`, `match_template/mods`, `match_*/mods`): лаунчер позволяет клиенту выключить опционал (вкладка «Моды», удаляет jar из клиентского `mods/`), но Forge-хендшейк жёстко сверяет сетевые каналы — серверный канал без клиентского = «Channels [...] rejected their client side version number» + «Terminating connection with client, mismatched mod list» (сообщение одно и для отсутствующего канала, и для несовпадающей версии — отдельной строки «missing» в NetworkRegistry нет). Инцидент 11.08.2026: matmos_tct (MAtmos, тогда опционал из `Pwpfiles/optional_mods/`) стоял на сервере в 4 местах, клиенты с выключенным опционалом не могли зайти. `build.bat` опционалы на сервер не копирует — заносятся вручную, при обнаружении на сервере jar из `optional_mods/` — удалять. **ИСКЛЮЧЕНИЕ с 11.08.2026: matmos_tct ПЕРЕВЕДЁН из опциональных в обязательные** (jar: `optional_mods/` → `mods/` в Pwpfiles, теперь НА сервере `PWP-Server/mods` + `match_template/mods` — иначе клиенты без MAtmos не заходили бы, а он обязателен; канал у него есть, так что держать на сервере обязательно). Регенерировать манифест после изменения состава: `Pwpfiles/gen.ps1` + `node PWP-Launcher/scripts/sign-file.mjs Pwpfiles/manifest.json`
- Переброс игроков между лобби и матчами: хост выбирается по IP игрока через `TransferHosts` (pwp-core-server): приватный IP игрока → LAN-адрес серверной машины (автоопределение, резерв `192.168.50.249`), иначе → `pigeo.asuscomm.com`. Причина: NAT-loopback роутера теряет обратные пакеты на повторные соединения к матч-порту (первый заход в матч работает, повторный — «превышено ожидание»). Точки вызова: `MatchAllocator` (transferPlayers/joinActiveMatch/joinMatchById), `MatchStatsTracker.scheduleServerShutdown`, `GameLogicEvents` (returnToLobby)
- Сборка: `gradlew build -x test` (все моды), `gradlew shadowJar` (в `core-service`), `gradlew runClient` (dev-клиент)
- Требования: JDK 17 (путь прописан в `gradle.properties`), Gradle 8.14 (wrapper), Forge 1.20.1-47.3.0, official mappings, кодировка UTF-8
