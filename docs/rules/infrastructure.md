# Правила: инфраструктура / запуск

Часть правил PWP. Полный индекс — корневой `AGENTS.md`.
**Перед изменением кода этого модуля/домена — прочитай этот файл; после изменений (новый модуль/фича, инцидент, фикс, изменённые правила сборки) — обнови его**: текст на русском, метки дат `(дд.мм.2026)`, удаляй устаревшее, если описание разошлось с кодом, секреты/токены не добавлять.

---

- MySQL (XAMPP), БД `pwp_core`; core-service на :8080; Caddy — HTTPS-прокси `https://pigeo.asuscomm.com` → localhost:8080 (Caddyfile в корне); MC-сервер :25565
- Discord RPC: лаунчер слушает `127.0.0.1:42157` (`POST /status` с `{"state":"lobby|match|playing|idle","nickname":...,"faction":...}`) и ставит статус в Discord. Мод шлёт статус через `LauncherStatusReporter` (pwp-warfare/client): `handleSyncGameData` постит lobby/match (своя фракция против вражеской), отключение от сервера — playing
- Матч-серверы поднимаются пер-матч из `match_template/` (директории `match_*` gitignored)
- **ОПЦИОНАЛЬНЫЕ МОДЫ НИКОГДА не ставить на сервер** (`PWP-Server/mods`, `match_template/mods`, `match_*/mods`): лаунчер позволяет клиенту выключить опционал (вкладка «Моды», удаляет jar из клиентского `mods/`), но Forge-хендшейк жёстко сверяет сетевые каналы — серверный канал без клиентского = «Channels [...] rejected their client side version number» + «Terminating connection with client, mismatched mod list» (сообщение одно и для отсутствующего канала, и для несовпадающей версии — отдельной строки «missing» в NetworkRegistry нет). Инцидент 11.08.2026: matmos_tct (MAtmos, тогда опционал из `Pwpfiles/optional_mods/`) стоял на сервере в 4 местах, клиенты с выключенным опционалом не могли зайти. `build.bat` опционалы на сервер не копирует — заносятся вручную, при обнаружении на сервере jar из `optional_mods/` — удалять. **ИСКЛЮЧЕНИЕ с 11.08.2026: matmos_tct ПЕРЕВЕДЁН из опциональных в обязательные** (jar: `optional_mods/` → `mods/` в Pwpfiles, теперь НА сервере `PWP-Server/mods` + `match_template/mods` — иначе клиенты без MAtmos не заходили бы, а он обязателен; канал у него есть, так что держать на сервере обязательно). Регенерировать манифест после изменения состава: `Pwpfiles/gen.ps1` + `node PWP-Launcher/scripts/sign-file.mjs Pwpfiles/manifest.json`
- **ParCool (паркур-мод, политика с 12.08.2026)**: мод обязательный (jar `ParCool-*.jar` + `ParCool-CompatibilityAddon-*.jar` в `mods/` всех серверов). Боевой паркур запрещён серверными лимитами — `serverconfig/parcool-server.toml`, секция `[Limitations]`: `limitation_imposed = true`, разрешены ТОЛЬКО `permit_ClimbUp` (забираться на блоки до 2 высоты) и `permit_Vault` (перелезание через заборы/ступени ~1–1.5 блока), остальные 23 `permit_* = false` (Roll/Flipping/BreakfallReady/Dodge/Tap/Slide/WallRun/WallJump/WallSlide/ClingToCliff/ClimbPoles/HangDown/JumpFromBar/FastRun/FastSwim/ChargeJump/CatLeap/SkyDive/Dive/RideZipline/Crawl/HideInBlock/QuickTurn/StartSwimByCrawl), `allow_infinite_stamina = false` (climb/vault тратят стамину). Файл конфига синхронизирован в 3 местах: `world/serverconfig/`, `match_*/<мир>/serverconfig/` и шаблон `match_template/world/serverconfig/` (создан 12.08.2026 — без него новые матч-серверы стартуют с дефолтом, где всё разрешено). Лимиты автоматически синхронизируются клиентам. Родной HUD стамины ParCool («молния») скрыт — в клиентском `Pwpfiles/config/parcool-client.toml` `stamina_hud_type = "Hide"` + `show_action_status_bar = false` (12.08.2026), вместо него pwp-limits рисует свою Squad-полоску (см. `docs/rules/limits.md`). При изменении клиентских конфигов — регенерировать манифест (`Pwpfiles/gen.ps1` + `node PWP-Launcher/scripts/sign-file.mjs Pwpfiles/manifest.json`). При изменении политики править все 3 файла одинаково + перезапуск серверов (serverconfig читается при старте мира, hot-reload нет)
- Переброс игроков между лобби и матчами: хост выбирается по IP игрока через `TransferHosts` (pwp-core-server): приватный IP игрока → LAN-адрес серверной машины (автоопределение, резерв `192.168.50.249`), иначе → `pigeo.asuscomm.com`. Причина: NAT-loopback роутера теряет обратные пакеты на повторные соединения к матч-порту (первый заход в матч работает, повторный — «превышено ожидание»). Точки вызова: `MatchAllocator` (transferPlayers/joinActiveMatch/joinMatchById), `MatchStatsTracker.scheduleServerShutdown`, `GameLogicEvents` (returnToLobby)
- Сборка: `gradlew build -x test` (все моды), `gradlew shadowJar` (в `core-service`), `gradlew runClient` (dev-клиент)
- **Инцидент 12.08.2026: сервер не стартовал с `NoSuchMethodError: Commands.literal(String)` из `PwpAdminCommand.register` (pwpcore)**: в `PWP-Server/mods` лежал НЕ-реобфусцированный jar (байткод ссылался на mojmap `Commands.literal`, а рантайм Forge 1.20.1 — SRG `m_82127_`). Диагностика: `javap -p -c` джарника из `build/libs` (искать `m_<цифры>`-имена вместо mojmap) + `javap` класса `net.minecraft.commands.Commands` из `server-*-srg.jar` в `PWP-Server/libraries`. Чинится пересборкой (`gradlew :<модуль>:build -x test` — `reobfJar` перезаписывает jar в `build/libs`) и деплоем в `mods` + `match_template/mods`. Признак нормы: `Length` jar меняется (40 309 → 40 605), в байткоде появляются SRG-имена
- **Правило гигиены сборки (с 12.08.2026)**: gradle НЕ удаляет старые jar из `build/libs` при смене version, а `build.bat` копирует на сервер и в `Pwpfiles/mods` ВСЕ `pwp-*.jar` — после пересборки рядом со свежим лежит старая версия, Forge/лаунчер может загрузить случайную. Каждый модуль должен иметь `jar.doLast`, чистящий свои старые jar (паттерн — `sbwchunkload/build.gradle` и `pwp-limits/build.gradle`). Инцидент 12.08.2026: `pwp-limits-1.0.2.jar` вернулся на серверы и клиент после сборки 1.0.3 (не работал Squad-HUD стамины/КД, оставалась паркурная «молния»). После изменения jar/конфигов в Pwpfiles — регенерировать манифест (`gen.ps1` + `sign-file.mjs`); лаунчер при обновлении сам удаляет из клиентского `mods/` jar, которых нет в манифесте (см. `mc/mods.rs`), и перезаписывает файлы с изменённым хешем
- Требования: JDK 17 (путь прописан в `gradle.properties`), Gradle 8.14 (wrapper), Forge 1.20.1-47.3.0, official mappings, кодировка UTF-8
