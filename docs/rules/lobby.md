# Домен: pwp-lobby

Вся правда о голосованиях лобби и их клиентских HUD-подсказках. Общая карта проекта — в корневом `AGENTS.md`.

| `pwp-lobby` | Лобби: голосование за карту/режим/фракции, старт матчей (в match-серверах отсутствует). Состояние для GUI сервер шлёт единым `LobbyStatePacket` (pwp-core-client/network) каждую секунду + при изменениях + при входе — клиент ничего не вычисляет сам. Клиентская фича «TAB / Vote Hint HUD» — в `pwp-core-client/gui/hud` (см. ниже). |

## Голосования (сервер, pwp-lobby)

- Цепочка: **карта (300 с, ускорение до 60 с при ≥90% голосов) → режим (120 с) → фракции (120 с) → матч**. Голосования не пересекаются (`LobbyMod.isAnyVoteActive()`), политика запуска матчей проверяется при старте голосования и матча.
- Команды: `/votemap`, `/votemode`, `/votefaction`, `/pwp server start|stopvote|autostart|status|stop`, `/pwp join`.
- Фазы `LobbyStatePacket`: IDLE=0, MAP=1, MODE=2, FACTION=3, MATCH_STARTING=4, MATCH_PLAYING=5. Пакет персональный (свой `my*Vote` каждому игроку).
- `leadingName` в пакете заполняется **только** для голосования за карту (и это сырое имя карты, не displayName). Клиентский HUD его не использует — лидера считает из массивов `voteCounts`/`mapDisplayNames`, `modeVoteCounts`/`modeDisplayNames`, `team1Votes`/`team2Votes`.

## TAB / Vote Hint HUD (клиент, 13.08.2026)

Собственное поведение клавиши TAB в лобби + ненавязчивые подсказки голосования. Код — в **pwp-core-client**, пакет `gui/hud`:

- `LobbyKeyMappings.java` — KeyMapping TAB («Открыть лобби-меню», категория «PWP», `KeyConflictContext.UNIVERSAL`, MOD-шина).
- `LobbyHudEvents.java` (FORGE-шина): `RenderGuiOverlayEvent.Pre` — cancel ванильного `PLAYER_LIST`, пока состояние лобби свежее; `Post` — точка ◉ + баннер **только на оверлее `CHAT_PANEL`** (событие срабатывает после каждого оверлея ~10-15 раз за кадр — без фильтра HUD перерисовывался бы десятки раз, был инцидент лагов 13.08.2026); `ClientTickEvent.START` — `consumeClick()` TAB → `PWPLobbyScreen.openScreen()`; `InputEvent.MouseButton` — клик по баннеру/точке ◉ тоже открывает меню (hit-зоны из `VoteHintToast.clickAt`, координаты — `MouseHandler.xpos/ypos` ÷ GUI scale, т.к. `InputEvent.MouseButton` и `RenderGuiOverlayEvent` в 1.20.1 не несут позиции мыши); `LoggingOut` — полный сброс.
- `VoteHintToast.java` — машина состояний показа: детект новой фазы (phaseId = счётчик, растёт при смене фазы И при «прыжке» таймера вверх > 30 с — перезапуск голосования без смены фазы), первичный показ при смене фазы + звук `UI_TOAST_CHALLENGE_COMPLETE` (pitch 1.0, volume 0.8), жизненный цикл 10 с (слайд с правого края 300 мс easeOutCubic → фейд 300 мс). **Повтор не чаще 30 с — только для «новичка»** (фаза не просмотрена: не открывал меню и не голосовал) и только при закрытом экране, БЕЗ звука — опытные игроки повторных уведомлений не получают (13.08.2026). Всё время — `System.nanoTime()`, FPS-независимо. **Производительность**: строки/размеры собираются ТОЛЬКО в `onLobbyState` (раз в секунду, на пакете) — рендер только draw; шрифт кэшируется лениво (рефлексия `PWPTheme.Fonts.display()` не по кадру).
- `VoteKeyHint.java` — кейкап-клавиша: ширина по фактической ширине текста (не ломается при GUI Scale), тёмный фон + рамка `BORDER_LIGHT`.

Правила поведения:

- **Свежесть состояния**: `PWPLobbyScreen.isLobbyStateFresh()` = последний пакет был ≤ 3 с назад (пакеты приходят раз в секунду). В матчах/после выхода пакетов нет → через 3 с весь перехват (TAB, PLAYER_LIST, HUD) отключается сам, без ручной очистки. Матчевое поведение TAB/player list НЕ меняется (в survival/adventure player list по-прежнему гасит pwp-limits — это его зона, не трогать).
- `PWPLobbyScreen.openScreen()` не открывается поверх другого экрана (guard `mc.screen != null`), повторный TAB при открытом экране — no-op. Открытие экрана (любое) помечает фазу просмотренной (`VoteHintToast.markViewed`).
- **Точка ◉** (10×10, правый верхний угол): цвет фазы (карта=`ACCENT`, режим=`TEAM_BLUE`, фракции=`TEAM_RED`); пульс alpha 0.4→1.0 (период 2 с, time-based) пока игрок не открывал экран в текущей фазе (`lastViewedPhaseId`), затем статичная alpha 0.5. Пульс НЕ перезапускается пакетами — только при смене phaseId. **Ховер на точку → тултип «Голосование идёт [TAB]»** (hit-зона 22×22 вокруг точки, тултип слева от неё); клик по точке/баннеру открывает меню (13.08.2026).
- **Баннер** (двухстрочный, правый край, вертикальный центр): ряд 1 — иконка-точка цвета фазы (единственный цветовой акцент) + заголовок слева, кейкап `[TAB]` справа; ряд 2 — строка лидера на всю ширину (13.08.2026: кейкап переехал в ряд 1, чтобы телу не ужиматься). **Ширина динамическая по контенту** (clamp 220–340, тексты эллипсис под доступное место — пустоты нет, за экран не выходит), высота по контенту. Лидер: map/mode — из массивов пакета, faction — «Синие: X · Красные: Y»; голосов нет → «Ожидание голосов...». **Проголосовал → «Вы проголосовали · <лидер>»** — статус и лидер вместе (был фикс 13.08.2026: раньше при голосе показывался только статус). Смена лидера/числа голосов НЕ перезапускает баннер — тексты обновляются на следующем пакете.
- HUD не рисуется поверх `PWPLobbyScreen`; все данные пакета проходят через null/empty-защиту (`safeName`) и обрезку по ширине (`fit`).
- Сброс при выходе: `clearCachedState()` + `resetInstance()` + `VoteHintToast.reset()` — никакого stale HUD после disconnect/перехода в матч.
