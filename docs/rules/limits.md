# Правила: pwp-limits

Часть правил PWP. Полный индекс — корневой `AGENTS.md`.
**Перед изменением кода этого модуля/домена — прочитай этот файл; после изменений (новый модуль/фича, инцидент, фикс, изменённые правила сборки) — обнови его**: текст на русском, метки дат `(дд.мм.2026)`, удаляй устаревшее, если описание разошлось с кодом, секреты/токены не добавлять.

---

| `pwp-limits` (v1.0.3) | Клиентские лимиты/правила боя: кулдаун спринт-прыжка (1.0 сек, конфиг `enableJumpCooldown` / `jumpCooldownSeconds`), скрытие ванильного HUD (хиты/голод/хотбар/XP/броня/прицел — свой Squad-HUD в `ClientOverlay`), блокировка F3/F3+B/F5 в Survival/Adventure. Конфиг: `<мир>/serverconfig/pwplimit-server.toml` (SERVER-тип Forge). |

## Ключевые решения (12.08.2026)

- **Синк конфига сервер→клиент**: Forge НЕ передаёт SERVER-конфиги по сети, поэтому клиент в мультиплеере работал бы с локальными дефолтами. Добавлен SimpleChannel (`network/NetworkHandler`, пакет `network/LimitsConfigPacket`): сервер шлёт `enableJumpCooldown`+`jumpCooldownSeconds` при входе игрока (`ServerEvents.onPlayerLoggedIn`) и при перезагрузке конфига (`PWPLimit.onConfigReload` на `ModConfigEvent.Reloading`). Клиентские механики читают ТОЛЬКО `client/LimitsConfigCache` (кэш, дефолты = дефолтам конфига), а не `ModConfig` напрямую. `ConfigScreen` после сохранения обновляет кэш сам (сингл; на сервере значения перекроются пакетом).
- **F5/F3 без мерцания**: сброс камеры раньше делался только в END-фазе тика — при удержании F5 камера на 1 тик уходила в третье лицо (дёргалась). Теперь в START-фазе (до ванильного `handleKeybinds`) проглатывается нажатие `keyTogglePerspective.consumeClick()` и гасится `renderDebug` — переключение не срабатывает вовсе; в END остаётся страховочный сброс камеры/хитбоксов.
- **Кд прыжка по игровым тикам** (`player.tickCount`), не по `System.currentTimeMillis` — не зависит от реального времени/лагов. Записи `ClientEvents.sprintJumpCooldown` чистятся на выходе (`ClientPlayerNetworkEvent.LoggingOut`) и по истечении.
- **Squad-HUD в `ClientOverlay`** (рисуется на `RenderGuiOverlayEvent.Post`/CHAT_PANEL, guard на `mc.options.hideGui` — при F1 не рисуется; гварды: не в меню, игрок жив). Три независимых полоски, все x=10, w=81:
  - HP-бар (y=guiH−32, h=7, фон `0x181C24`/рамка `0x1E222A`, заливка зелёная `0x3D7A40`, красная `0xA53D3D` при <30%): фейдится — виден только при получении урона (60 тиков) или активном КД прыжка.
  - Стамина ParCool (y=guiH−39, h=2, белая заливка `0xFFFFFF`): видна только пока стамина неполная (тратится на ClimbUp/Vault), плавный lerp значения (восстановление = медленный рост белой полосы), фейд при полном восстановлении. Данные — публичный API `com.alrex.parcool.api.Stamina.get(player)` (`getValue`/`getMaxValue`), синхронизируется клиенту самим ParCool; чтение в try/catch `Throwable` (нет мода — полоска просто не рисуется).
  - КД спринт-прыжка (y=guiH−43, h=2): показывается только пока КД активен, показывает ОСТАТОК (убывает), цвет — плавный градиент по остатку: >66% белый `0xFFFFFF`, 33–66% оранжевый `0xC8812A`, <33% красный `0xA53D3D` (трехцветный lerp по каналам, `cdGradientColor`/`lerpColor`). Раньше была под HP-баром оранжевой — перенесена над стаминой (12.08.2026).
- **Зависимость от ParCool**: `pwp-limits/build.gradle` — `compileOnly files("${pwpfiles}/mods/ParCool-1.20.1-3.4.3.3.jar")` (паттерн sbwchunkload; pwpfiles из корневого build.gradle). Ссылки на классы ParCool — ТОЛЬКО в `Dist.CLIENT` классе `ClientOverlay` (серверная часть модуля их не трогает; класс на сервере не загружается). **Гигиена build/libs (с 12.08.2026)**: `jar.doLast` удаляет старые `pwp-limits-*.jar` из `build/libs` — build.bat копирует ВСЕ jar модуля на сервер, и без гигиены после пересборки с новой версией на сервер возвращаются старые (инцидент 12.08.2026: 1.0.2 вернулся в `PWP-Server/mods`, `match_template/mods` и `Pwpfiles/mods` — клиент загружал случайную версию: не было ни КД-полоски, ни стамины, а паркурная «молния» оставалась). `ConfigScreen` валидирует 0.1–60 сек с сообщением об ошибке (раньше невалидный ввод молча игнорировался).
- Блокировки F3/F3+B/F5 жёсткие (конфигов вкл/выкл нет), работают только в Survival/Adventure. Всё клиентское — не античит.

## Уроки

- SERVER-конфиг Forge в 1.20.1 не синхронизируется по сети — для любых настроек, влияющих на клиентское поведение в мультиплеере, нужен свой пакет (паттерн как `LobbyStatePacket` в pwp-lobby).
- `TickEvent.ClientTickEvent.START` стреляет ДО `Minecraft.handleKeybinds` — это точка, где можно проглотить нажатия клавиш (`KeyMapping.consumeClick()`) без миксинов.
- **Инцидент 12.08.2026 — «lost connection: Disconnected» при входе**: `ModConfigEvent.Reloading` срабатывает на mod-bus НЕ только на сервере, но и на клиенте при приёме синхронизированного SERVER-конфига в login-хендшейке (`ConfigSync.receiveSyncedConfig` в `HandshakeHandler.handleConfigSync`). Слушатель `PWPLimit.onConfigReload` вызывал `LimitsConfigPacket.broadcast()` → `PacketDistributor.ALL.noArg()` → внутри `PacketDistributor.lambda$playerListAll$3` обращение к приватному `getServer()`, который на физическом клиенте = null → NPE в хендшейке → клиент получает «lost connection: Disconnected» и крутит цикл переподключения (после «Mod Verifier: accepted», т.к. это уже конец login-фазы). Фикс: гард в `broadcast()` — `if (FMLEnvironment.dist != Dist.DEDICATED_SERVER) return;`. Правило: любые рассылки `PacketDistributor.*` из обработчиков событий, которые могут сработать и на клиенте, обязаны иметь dist-гард (или вызываться только с сервера).
