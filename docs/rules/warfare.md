Часть правил PWP. Полный индекс — корневой `AGENTS.md`.
**Перед изменением кода этого модуля/домена — прочитай этот файл; после изменений (новый модуль/фича, инцидент, фикс, изменённые правила сборки) — обнови его**: текст на русском, метки дат `(дд.мм.2026)`, удаляй устаревшее, если описание разошлось с кодом, секреты/токены не добавлять.

| `pwp-warfare` | Основной контент: техника, оружие (M2 Browning, AGS-30, миномёт), блоки (`vehicle_spawner`, `rally`, `fob`, `hub_block`, `game_start_trigger`, ящики снабжения), анимации/гео, команды `/pwpwarfare`. Зависимости: GeckoLib 4.4.9, Curios 5.14.1, Simple Voice Chat API 2.6.20. **Дроны uncomplicated-fpv (деплой-система, с 05.08.2026)**: штатный мгновенный спавн UFPV-предметов блокируется (`DroneDeploymentEvents.onRightClickBlock` HIGHEST), вместо него канальный деплой — ПКМ по земле, дрон сразу спавнится в точке (неуязвим, флаг `WARFARE_DroneDeploying`), установка 4с (конфиг `droneDeployTimeTicks`), затем полный БК (FPV — 1× rpg_rocket_standard, мавик-с-дропом — 2× rgo_grenade через `DroneCompat.quickLoadAttachment`), полная энергия, теги `WARFARE_VehicleTeam`/`WARFARE_DroneOwner` (E_TEAM ставится в completeDeploy — раньше не ставился, дрон был «без команды»). Кулдаун 45с ОТ СТАРТА установки (`droneDeployCooldownTicks`, потеря дрона не продлевает), лимиты `droneMaxActivePerPlayer`=2 и `droneMaxActivePerType`=1 (1 FPV + 1 мавик). Отмена: смерть ИЛИ сдвиг по XZ >2.5 блока от точки (юзер «должен стоять на месте»; раньше движение не прерывало — баг времени делал отмену ложной; ВАЖНО: единый источник времени — серверный `getTickCount()`, НЕ `level.getGameTime()`, иначе elapsed = tick-start вечно отрицательный и деплой зависает). Дальний клик (с 12.08.2026): стандартная точка установки — клик, но если кликнул дальше `droneDeployMaxRange`=2 блоков (край досягаемости/случайно), точка ЗАТЯГИВАЕТСЯ к игроку (кламп X/Z на круг 2 блока вокруг игрока, Y — уровень ног) — иначе дрон спавнился за порогом стойки 2.5, установка мгновенно отменялась и кулдаун сгорал впустую (инцидент 12.08.2026: «далеко пкмишь — сразу в кд»). Максимум захардкожен <2.5, чтобы канал гарантированно не отменялся по дистанции; клиент ничего не меняет — позиция из пакета уже закламплена. КУЛДАУН деплоя (`P_CD_UNTIL`) — наоборот, в МИРОВОМ времени `level.getGameTime()` (тики сохраняются в level.dat): серверный tickCount сбрасывается при рестарте сервера/матча, а persistentData игрока переживает рестарт — cdUntil оставался большим, tickCount малым → кулдаун «висел бесконечно» (инцидент 06.08.2026: «кд плюсует бесконечно»). Каждый деплой ПЕРЕЗАПИСЫВАЕТ cdUntil абсолютным значением (gameTime + CD) — обновление, не прибавление. Проверка «Установка уже идёт» стоит РАНЬШЕ CD-проверки (спам ПКМ во время установки показывает правду, а не «Кулдаун»). Разбор (снифт+ПКМ) ЗАПРЕЩЁН — предмет не возвращается. Во время установки (`E_DEPLOYING`) ВСЕ ПКМ по дрону отменяются в `onEntityInteract` (монитор не подключится, инвентарь не откроется) + страховка-миксин `DroneConnectMixin` на `AddonDroneEntity.beginRemoteControl` (remap=false, false если E_DEPLOYING — ловит обход события своим пакетом UFPV). Дрон-зомби: E_DEPLOYING без активного деплоя владельца (офлайн/другой дрон) — деспаун в tickIdleDespawn; залипшее P_DEPLOY_* чистится в `PlayerLoggedInEvent` (дрон сносится). Брошенный дрон (на земле без управления) — авто-деспаун 60с (`droneIdleDespawnTicks`=1200, было 15с) с сообщением владельцу + false-пакет. Чанк-страховка: управляемый дрон в не-тикающемся чанке → `DroneCompat.forceSignalLoss` (честный обрыв связи) + remove + сообщение/пакет владельцу. Клиент: `PacketDroneDeployState` (каждые 5 тиков, только игроку канала; поле totalTicks для честного таймера; поле mode: 0=установка, 1=перезарядка) + `DroneDeployOverlay` (кольцо прогресса 16 сегментов + ТРИ вращающиеся лопасти по 120° ТОЛЬКО при установке; время = `level.getGameTime()+frameTime` — НЕ partialTick, иначе лопасть «стоит» и дёргается; маркер-кольцо НАД дроном y+1.3, не на земле; клиентский lerp прогресса для плавности; авто-скрыл: >60 тиков без пакетов — гуишка гаснет; hideGui учитывается; звук — короткий ванильный NOTE_BLOCK_BIT раз в 20 тиков). **Дрон-подсумок** `pwpwarfare:drone_ammo_pouch` (только Drone Operator, ×2 слот 10): ПКМ по СВОЕМУ мавику (на земле, без управления, не в канале) → канал перезарядки 2с (`droneReloadTimeTicks`=40, та же анимация с mode=1, без лопастей) → расход 1 подсумка при старте + `quickLoadAttachment(rgo_grenade ×2)` + звук/частицы; чужой мавик/в воздухе/под управлением — отказ. **РЭБ uncomplicated-fpv через стройку**: `RebConstructionBlock`/`RebConstructionBlockEntity` (паттерн M2, блюпринт за маты 150/60, `rebBuildCost`/`rebMiniBuildCost`), структуры PacketBuildRequest 24 (REB) / 25 (MINI REB), в радиалке StaticGunRadialScreen (секторы REB/MINI REB вместо отключённых M2/AGS, меню переименовано в EMPLACEMENTS), макет — блок-призрак. Время стройки копанием 500/250 тиков (`rebBuildTimeTicks`/`rebMiniBuildTimeTicks`), лимит `rebMaxPerTeam`=3. Завершение — спавн `uncomplicatedfpv:reb`/`reb_mini` с тегом команды. `RebDeploymentEvents`: прямое использование предметов reb/reb_mini заблокировано, снифт+ПКМ своей команде = демонтаж БЕЗ возврата предмета, вкл/выкл — только своей команде. **Текстурки макета (с 06.08.2026)**: макеты РЭБ — ПРОСТЫЕ полупрозрачные боксы БЕЗ текстур, как у остальных построек (стены/колючка): зелёный валидный / красный invalid. Фит `s=clamp(min((w-14)·guiScaleX/capW,(h-14)·guiScaleY/capH), 0.3, 200)` + центровка `translate(-center*s)` до `scale(s)` (внешний scale к chain-результату применяется целиком — линейно). ФОРМУЛА И ЮНИТЫ (инцидент 12.08.2026 «пушка в лоадауте и тултипе мелкая»): каптчер мерит модель в post-BEWLR-единицах (~2.74 у винтовки), НЕ в пикселях — поэтому честный `s` для заполнения рамки ~18…100, а НЕ 1…2. По логу: `box=80x40 raw=24.05`, `box=152x43 raw=50.29`. ДВЕ причины мелкости: (1) верхний лимит клампа был `6.0` (остался от эры, когда s был 0.3…2.2 по старому bbox-фиту) и обрезал любой честный фит до 6 → пушка в ~8px; поднят до `200.0`. (2) Каптчер мерит на identity-стеке, а рендер идёт через `gui.pose()` с базой `scale(1/guiScale)` — фит нормируется по ТОЧНЫМ осям экрана `guiScaleX=screenW/guiScaledW`, `guiScaleY=screenH/guiScaledH` (НЕ округлённый `getGuiScale()` — работает на дробном Auto-масштабе). Центровку не трогаем (компенсирующий `translate(-center*s)` гасит сдвиг точно, guiScale-независим). Фолбэк без капчи (модель не догружена): `fallbackScale` база×тип. Кэш по стек+ориентация. Рюкзак в лоауте — сетка 4×N (¼ ширины PRIMARY, клик = выбор, альтов не раскрывает). Список отрядов скроллится колесом (`scrollSquads`) + авто-ревил своего отряда при изменении состава (`autoRevealMySquad` в tick). RoleGrid: ОДНА категория = ОДНА строка мелких иконок (28→22px адаптивно, без скролла), sticky `hoveredKit` (превью не пропадает при уходе мыши в сторону).
