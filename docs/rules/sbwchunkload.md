# Правила: sbwchunkload

Часть правил PWP. Полный индекс — корневой `AGENTS.md`.

| `sbwchunkload` | Серверный аддон чанк-лодинга снарядов (v2.0.0+): ОДИН миксин на vanilla `ServerLevel.addFreshEntity` (SRG `m_7967_`) → `ProjectileTracker.register()` (публичный API, api/ProjectileTracker: register/unregister/register(Entity,Profile) — любой мод может регистрировать свои снаряды без миксинов). Модульная архитектура (каждый класс — одна задача, только публичные интерфейсы): classifier/ProjectileClassifier — кэш `ConcurrentHashMap<Class<?>, Profile>`, первый раз instanceof `ProjectileLike` (pointblank = FCL-трубы) / `FastThrowableProjectile`+`ProjectileEntity`+`TaserBulletEntity` (SBW = НУРС/ПТУРы/бомбы/автопушки/7.62-пули; всё наследуемое аддонами FCP/VVP/DragonRise подхватывается АВТОМАТИЧЕСКИ; исключения: C4/Claymore/EDD/мины не летят), профиль по скорости первого замера: FAST_LINEAR/SLOW_LINEAR/BALLISTIC/HEAVY/STATIC → state/ProjectileState (WeakReference, минимум полей, Minecraft-механику не знает) → scheduler/TimingWheel (20 бакетов, 1 бакет в тик — НЕТ перебора всех снарядов каждый тик; снаряд сам говорит «через N тиков») → corridor/ChunkRasterizer (DDA по XZ — ВСЕ пересекаемые чанки, ширина `corridorWidth`) + ChunkCorridor.diff (added/removed) → ticket/ChunkTicketManager (ensureLoaded/release; TicketEntry{refCount, lastRefresh, expirationTick}; refcount-дедуп: N снарядов в чанке = 1 тикет; освобождение ПО TTL — `removeRegionTicket` НЕ вызывается, тикет ванили умирает сам ~5 сек) → watcher/SimulationDistanceWatcher (уровень тикета, первый тик + раз в 100). Smart-update: пересчёт коридора только если сменился чанк / снаряд вылетел из прогретого коридора / Δскорости >10% / Δнаправления >20°, иначе — простое продление. ЗАЩИТЫ (лимиты, всё в конфиге): maxTrackDistanceBlocks (2000) — трек от спавна; maxTrackAgeTicks (1200); maxTrackedProjectiles (300) — скип новых; maxActiveTickets (512) — скип новых тикетов (кэш-счётчик activeCount); stationaryThresholdUpdates (10) — снятие лежащих гранат/зависших ракет (M18 дымит 30+ сек = вечный тикет); World Border — тикеты за границей мира НЕ ставятся (иначе ваниль генерирует чанки до бесконечности за летящим за границу снарядом) + снаряд за границей снимается сразу (SRG m_61937_). Причины снятия видны в /sbwchunkload status Конфиг: `<мир>/serverconfig/sbwchunkload-server.toml` — ВСЁ без перекомпиляции (bullet/rocket/heavy/ballistic.interval+minimum/maximumLookahead, predictionMultiplier, ticketTTL, corridorWidth, debug; старые ключи сохранены, чтобы прод не сбросил настройки). Debug: команда `/sbwchunkload status|config` (permission 2). **Дроны (v2.2)**: `drone/DroneTracker` — ОТДЕЛЬНЫЙ путь от снарядов (проджектайл-пайплайн не трогает), те же функции: тикеты ChunkTicketManager (уровень min(3,sim), refcount, TTL, дедуп, world border), `instanceof com.atsuishio.superbwarfare.entity.vehicle.DroneEntity` (покрывает uncomplicated-fpv FPV/Mavic — без чанк-тикетов сигнальная связь «молча умирает» на границе прогруза). Правила: трек ПОКА ДРОН В ВОЗДУХЕ ИЛИ ПОД УПРАВЛЕНИЕМ (контроль — `DroneEntity.CONTROLLER`), снятие по onGround ТОЛЬКО после `GROUND_GRACE_UPDATES`=10 интервалов без управления (~5с) — мгновенное снятие рвало трек при канальном деплое, и после взлёта дрон ждал полный скан (10с) и успевал вылететь за прогруз и замерзнуть (инцидент 05.08.2026: «дрон не загружает чанки»); интервал `drone.interval`=10, упреждение `drone.lookahead`=16 блоков, лимит `maxTrackedDrones`=8, полный скан уровней раз в 100 тиков. Регистрация — МГНОВЕННАЯ из миксина `LevelAddFreshEntityMixin` (`DroneTracker.register`), скан — только страховка (дрон летит 20-40 блоков/сек и может вылететь за прогруз быстрее скана). ГИГИЕНА JAR: gradle НЕ удаляет старые jar из build\libs при смене version, а build.bat копирует ВСЕ sbwchunkload-*.jar на сервер → Forge грузил случайную версию (на сервере лежали 11 копий 1.0.0-2.1.0, из них 2.0.0 без DroneTracker) — в `sbwchunkload/build.gradle` task 'jar' doLast удаляет все sbwchunkload-*.jar из build\libs кроме свежесобранного; compileOnly geckolib обязателен (DroneEntity.CONTROLLER тянет суперкласс GeoEntity — иначе «cannot access GeoEntity»). КЛЮЧЕВЫЕ УРОКИ: 1) уровень тикета = `min(3, simulationDistance)` — сущности в 1.20.1 тикаются только в чанках с distance <= simulationDistance, уровень выше = загруженный, но «мёртвый» чанк (инцидент 05.08.2026); 2) НЕЛЬЗЯ `TicketType.PORTAL` с Integer-значением — `Ticket.compareTo` при равных типе/уровне кастует значение к типу соседнего тикета (BlockPos) → ClassCastException (краш матч-сервера 05.08.2026 14:33); свой `TicketType<Integer> sbwchunkload:projectile` безопасен; 3) smart-проверка = `isPositionEntityTicking` (SRG `m_143340_`), НЕ `isLoaded` — между view и sim чанки загружены, но сущности не тикаются, из-за isLoaded мод не давал эффекта (инцидент 05.08.2026); 4) пули (FAST_LINEAR, ~24 блока/тик) — интервал 1 + первый коридор сразу при спавне, иначе вылетают за прогретый коридор; 5) Server-only (секция `server` mixins.json), клиентам не раздаётся; 6) сборка ТОЛЬКО `gradlew build`/reobfJar (без reobf = mojmap-байткод → NoSuchMethodError в SRG-рантайме, инцидент 05.08.2026). Компиляция — прод-жарники SBW 0.8.9-final + pointblank 1.11.1 из Pwpfiles (compileOnly) |
