# Правила: античит

Часть правил PWP. Полный индекс — корневой `AGENTS.md`.
**Перед изменением кода этого модуля/домена — прочитай этот файл; после изменений (новый модуль/фича, инцидент, фикс, изменённые правила сборки) — обнови его**: текст на русском, метки дат `(дд.мм.2026)`, удаляй устаревшее, если описание разошлось с кодом, секреты/токены не добавлять.

---

- **Java-агент НИКОГДА не кикает сам** — только репортит на core-service и кикает по ответу `{action: kick}` (архитектура PJM Launcher). Инцидент 04.08.2026: локальный сканер маркеров убивал игру из-за класса `CalendarAstronomer$Horizon` (ванильная библиотека ICU4J, слово «Horizon» совпало с маркером чит-клиента) — локальных киков больше нет
- Код агента: `PWP-Launcher/anticheat-agent/` (`Agent.java` + `O.java` — XOR-обфускация маркеров, сборка `build.ps1` + ProGuard `agent.pro`, ключ модуля `java.net.http` в libraryjars). Публикация: `Pwpfiles/anticheat/agent.jar` + SHA-256 в `artifacts.json` + подпись `node PWP-Launcher/scripts/sign-file.mjs artifacts.json` (ключ в `%APPDATA%\.pwplauncher\.private\ed25519-private.pem`, тот же, что подписывает manifest.json)
- Агент ходит на сервер напрямую (`-Dac.url`, заголовок `X-Launch-Token`): `GET /api/v1/launcher/anticheat/rules` (правила {pattern,matchType,hash,severity} + version), `POST /detect` и `/files` и `/heartbeat` (отвечают `{action: kick|none}`; heartbeat продлевает сессию на 30 мин и возвращает `blacklistVersion` для ре-фетча). Seed-маркеры (severity 0) — только телеметрия, кикают лишь правила из БД с severity >= banSeverity (конфиг `anticheat.banSeverity`, дефолт 100 = всё report-only)
- Эвристика `illegal-class-name` (нестандартные символы в имени класса) с 04.08.2026 применяется ТОЛЬКО к классам вне доверенных корней: лаунчер передаёт `-Dac.trusted` (файл со списком корней `mods/` + `libraries/`), классы из них и bootstrap/jrt не проверяются. Причина: реворк 04.08.2026 потерял trusted-проверку и агент слал 20 фейковых детектов на каждый запуск игры (Forge/mixin/Nashorn генерируют рантайм-классы с нестандартными именами; во всех jar-ах игры нелегальных имён нет). Сканирование по блэклисту (hash/строки) работает по всем классам без исключения. Пойманные имена агент дополнительно пишет в `ac_illegal_names.log` рядом с kick-флагом (сервер имя класса не хранил — столбец `details` добавлен в `anticheat_detections` с 04.08.2026)
- `anticheat_detections`: столбец `details` (имя класса/детали), дедуп одинаковых `(player_uuid, type, signature)` в окне 10 минут (один буст = одна запись), TG-алерт шлётся только на первую запись буста
- Таблица `anticheat_blacklist`: match_type = substring|exact|word|regex|hash|string-literal, колонки `hash` (SHA-256 байткода) и `updated_at` (версия правил); `anticheat_sessions.revoked` — отзыв сессии. Админка: `/api/v1/admin/anticheat/signatures`
- `AuthMiddleware`: `/api/v1/launcher/anticheat/*` (кроме `artifact/`) пропускает по валидному `X-Launch-Token` (или существующему токену для `/heartbeat` — воскрешение истёкшей сессии), иначе падает в обычный HMAC лаунчера. Не блокировать лаунчер-вызовы (init/blacklist идут с X-PWP-Sign без launch-токена)
- Остальные слои без изменений: нативный агент `anticheat.dll` (watchdog «java-agent=up», module-unknown, скриншоты DXGI), GUARD лаунчера, процесс-скан, P5-эндфорс через игровой сервер (`/api/v1/launcher/p5/*`)
