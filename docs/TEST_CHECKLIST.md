# Ручная проверка этапов 1–2 (тестовый сервер)

Отмечай `[x]`, при провале — записывай фактический результат и строку лога. Логи сервера: `logs/latest.log`.

## 0. Подготовка
- [ ] **Комплект модов клиента и сервера один и тот же**, собран из ветки `rewrite/stage-2`. На клиенте ОБЯЗАТЕЛЬНЫ: `pwp-api`, `pwp-core-client`, `pwp-cosmetics`, `pwp-warfare` (+ остальные pwp-* по манифесту). На сервере дополнительно `pwp-core-server` (+ `pwp-lobby` в лобби).
  - Ожидание: без `pwp-core-client`/`pwp-cosmetics` Forge показывает экран «отсутствует обязательный мод», а не краш `NoClassDefFoundError: PWPSelectionScreen` (было в логе 15.11.2026 — в Prism-инстансе лежали только pwp-api и pwp-warfare).
- [ ] Версии сторонних модов как на проде: SBW **0.8.9-final**, TaCZ **1.1.8-hotfix**, pointblank 1.11.1, uncomplicated-fpv 1.0.0, sbwchunkload из этой сборки (2.2.1). Другие версии (например SBW 0.8.9.2, TaCZ 1.2.0, sbwchunkload 2.4.0) — миксины могут не примениться.
- [ ] Сервер: задан `PWP_API_KEY` или `config/pwpcore.txt`, core-service запущен.
- [ ] Сделать копию мира **до** первого запуска новой версии (для проверки отката, п. 3.4).

## 1. Подключение и протокол
1. [ ] Зайти клиентом старой версии на новый сервер → отказ «несовпадение версий канала» (`pwpwarfare:main`=4, `pwp_core_client:network`=3), не краш.
2. [ ] Зайти клиентом новой версии → вход успешен, в логе клиента нет `NoClassDefFoundError` / `Invalid message`.
3. [ ] В логе клиента нет строк `PWP_API_KEY`/`pwpcore.txt` (ключ на клиенте больше не читается).
4. [ ] **Установка через лаунчер с pwp-api:** чистая установка лаунчером → в `mods/` есть `pwp-api-*.jar` (он есть в манифесте), игра стартует, вход на сервер успешен. Если `pwp-api` нет — Forge показывает экран «отсутствует обязательный мод pwpapi», а не краш.

## 2. Асинхронность и антиспам (этап 1, доработки)
1. [ ] Меню скинов: надеть купленный скин → надет, обычный игрок не может надеть некупленный («Этот скин вам не принадлежит»).
2. [ ] Быстро кликнуть «надеть» 5 раз подряд → срабатывает один запрос, остальные — «Подождите, предыдущий запрос ещё выполняется».
3. [ ] Нажать «надеть» и сразу выйти с сервера → сервер не падает, в логе нет исключений; после повторного входа экипировка соответствует БД.
4. [ ] Админ (op 2+): редактор китов фракции → сохранить кит → «сохранено»; двойное быстрое сохранение → второе отклонено с «Подождите…».
5. [ ] Выключить core-service, сохранить кит → «Кит не сохранён в core-service — повторите позже».
6. [ ] `/voicemute <игрок> 1 test` → игрок получает сообщение; если цель вышла до ответа — команда завершается без ошибок.

## 3. Данные игрока (capability) и миграция
1. [ ] Первый вход на мир со старыми данными → кит, отряд, роль лидера сохранились. В логе: `Миграция <ник>: N ключей WARFARE_* скопировано в capability`.
2. [ ] Повторный вход → строки миграции нет (маркер `pwp_migrated_from_persistent`).
3. [ ] Выбрать кит, применить (PendingKit снят), перезайти → PendingKit не вернулся.
4. [ ] **Откат:** остановить сервер, поставить старую версию модов на копию мира после п. 3.1 → кит/отряд на месте (старые ключи `WARFARE_*` в persistentData не удалены). Вернуть новую версию.
5. [ ] Смерть → после респавна: отряд, лидерство, текущий кит, кулдауны ресапплая сохранены; нок сброшен.
6. [ ] Возврат из Энда (через портал, без смерти) → сохраняется всё (кулдаун деплоя дрона, ограничение базы за тимкилл, отряд, кит), кроме каналов дронов и флага мейн-зоны.
7. [ ] Нок → «сдаться» → респавн: состояние нока снято, клиенты видят игрока стоящим.
8. [ ] **Возврат из Энда во время установки дрона:** начать деплой дрона и войти в портал Энда/вернуться → канал установки у нового игрока НЕ продолжается (нет «вечной» гуишки), дрон-зомби деспавнится, кулдаун деплоя сохранился; повторный деплой после кулдауна работает.
9. [ ] **Откат после смерти:** на копии мира с новой версией выбрать кит, вступить в отряд, умереть и респавниться; остановить сервер, поставить старую версию модов → отряд, лидерство и кит на месте (ключи продублированы в persistentData при смерти).

## 4. Время (GameClock)
1. [ ] Деплой дрона → кулдаун 45 с → рестарт сервера → кулдаун не «бесконечный», истекает по мировому времени.
2. [ ] Канал установки дрона идёт 4 с и завершается (не зависает).
3. [ ] Кулдаун ресапплая у хаба/ящика после рестарта сервера ведёт себя корректно.

## 5. Мир матча (реестры WarfareWorldData)
1. [ ] Загрузить существующий мир матча → точки захвата, мейн-зоны, хабы, ралли, станции техники, отряды, метки на месте.
2. [ ] Изменить что-то (поставить хаб, создать отряд), перезапустить сервер → изменения сохранились.
3. [ ] Мир со старым ключом станций `MainSupplies` → станции техники загружены.

## 6. Загрузка китов и отложенный деплой
1. [ ] Старт матча при работающем core-service → в логе `KITS фракции … загружены`, деплой работает сразу.
2. [ ] Остановить core-service, применить map_config (старт матча) → в логе каждые 10 с ошибка загрузки с номером попытки.
3. [ ] Нажать «Деплой» → сообщение «Загрузка китов…», игрок остаётся на экране.
4. [ ] Включить core-service → в течение ~10 с киты загружаются, игрок спавнится автоматически с выбранным китом.
5. [ ] Повторить п. 3, затем сменить кит → «Выбор кита изменён — нажмите «Деплой» снова», автоспавна нет.
6. [ ] Повторить п. 3, затем сменить команду → «Команда изменена — деплой отменён».
7. [ ] Повторить п. 3, выйти с сервера, включить core-service → ошибок нет; после входа автоспавна нет.
8. [ ] Отложенный деплой на роль, которая к моменту загрузки заполнилась → «Кит … недоступен (Team Full …)! Спавн без кита.»
9. [ ] Деплой отложен («Загрузка китов…») → админ перезапускает матч (новый map_config) → «Матч перезапущен — нажмите «Деплой» снова», автоспавна нет.
10. [ ] **Одиночная игра — повторное открытие мира:** открыть мир с матчем, выйти в главное меню, открыть его (или другой мир) снова → киты грузятся заново (`KITS фракции … загружены`), деплой работает, ошибок в логе нет.

## 7. Отряды (сеть v2, по пакету на действие)
1. [ ] Создать отряд с именем и без имени (имя из NATO-алфавита).
2. [ ] Вступить, выйти, вступить в закрытый (отказ) и полный (отказ).
3. [ ] Лидер: закрыть/открыть, повысить участника, кикнуть участника → в чате «X исключён из отряда <name>» (не «Оффлайн-лидер…»).
4. [ ] Участник удаляет офлайн-лидера → лидерство переходит, в чате «Оффлайн-лидер X был удалён из отряда <name>».
5. [ ] Огневые группы: назначить командиров Браво/Чарли, добавить/убрать участника.
6. [ ] Распустить отряд → все участники вне отряда, CMD команды сброшен, если это был отряд командира.
7. [ ] Во всех действиях список отрядов у всех игроков в измерении обновляется сразу.

## 8. Запросы данных GUI (единая система)
1. [ ] Лобби: профиль, лидерборд (листание страниц), вкладка скинов — данные приходят.
2. [ ] Редакторы (op 2+): список фракций, техника фракции, деталь техники, киты фракции, скины — открываются.
3. [ ] Большой каталог скинов/техники (> 32 КБ JSON) загружается полностью, экран не «висит».

5. [ ] Админ-действия: сохранить/удалить скин, удалить технику фракции → результат «успех/ошибка» приходит; не-админ — «Недостаточно прав».

## 9. Лобби

## 10. Матч: захват, тикеты, лимиты ролей
1. [ ] AAS: захват нейтральной точки → уведомление, у защитников −captureDeduction, у атакующих +gainCap.
2. [ ] AAS: нейтрализация точки противника → у владельца −ticketPenalty, у атакующих +gainNeut.
3. [ ] Invasion: захват → атакующим +бонус (по умолчанию 100); потеря последней точки защитниками → их тикеты 0, победа атакующих.
4. [ ] Тикеты ≤ 0 → экран победы, статистика уходит в core-service.
5. [ ] Меню деплоя: роль с лимитом команды/отряда показывает «Team Full (x/y)» / «Squad Full (x/y)».
6. [ ] Четвёртая роль FIRE_SUPPORT в отряде → «Max 3 Fire Support per Squad» в меню и отказ при спавне.
7. [ ] **Респавн живым игроком отклонён:** живым на поле открыть меню деплоя (K) и нажать «Деплой» на рали/ФОБ → «Вы уже на поле — деплой доступен только после смерти», телепорта и выдачи кита нет, материалы ФОБ не списаны. После смерти тот же деплой работает.
8. [ ] **Выбор занятого кита отклонён:** роль с лимитом 1 занята другим игроком (выбрана или текущая) → выбор → «Кит … недоступен: Team Full (1/1)», PendingKit не изменился (в меню выделен прежний кит).
9. [ ] **Выбор чужого/лидерского кита отклонён:** не-лидер выбирает лидерский кит (меню открыто до потери лидерства) → «Squad Leader only»; кит, которого нет у команды игрока → «кит не найден у вашей команды». Лидер выбирает лидерский кит — успешно.
10. [ ] Смерть с CurrentKit, лимит которого за время смерти снизили в редакторе китов до уже занятого → после деплоя «Кит … недоступен (…)! Спавн без кита.»
